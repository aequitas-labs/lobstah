# CLI additions since 0.5.5

This audit compares `apps/cli/src/main.ts` and `usage.ts` at `v0.5.5`, current `main`, and the current heads of open PRs #86, #88, #90, and #91 on 2026-09-29. It covers 40 new command, subcommand, option, or address forms. It does not count a changed implementation behind an old spelling as a new CLI surface. The test/docs column below refers to repository paths, not claims of external adoption.

Verdicts: **32 keep** (including two temporary migration forms), **4 fold**, **1 replace with brief text**, and **3 remove**. The first cuts are follow-up-placement flags on `send`, the title helper in PR #88, and `prs sync`. None is changed by this audit.

The rule column uses the owner's four tests: **1** daemon/runner state or timing; **2** a hook, glass, pet, or skill calls it; **3** a person saves real work; **4** deterministic safety. A dash means none is evidenced. `T` means both plugin trap skills; `M` both plugin lobstah man skills; `H` both plugin hook manifests; `G` the glass client/server; `P` the pet; `D` daemon, runner, or pick loop. `Human only` means no programmatic caller was found; it is not evidence of actual use. The caller register below names the files. In the test/docs column, `Y` means there is a focused test and a prose entry in `usage.ts` or docs; `N` says which is missing. A test is not itself a production caller.

## Keep

Rows 1, 3–21, 26–34, 36–37, and 40 meet a stated rule. The important boundary is not syntax count alone: `soak beat`, pause timing, held-watch release, and human gates change supervised state safely and deterministically; the pet's JSON read and glass's session link have real consumers. The service verbs replace platform-specific process commands for a person. The two `watch backfill` forms are migration tools, not daily worker verbs. Keep them only while historic dispatches still require migration; remove both after that is established.

## Fold into an existing command or option

Rows 23–25 duplicate `dispatch --follow-up --harness/--model/--for`. They only matter when `send` creates a new follow-up for finished work. Keep `send <id> <message>` as the simple route to live or queued work, but move choice of a new worker to explicit `dispatch --follow-up`. Row 35 has a safe default hold reason and no caller; `watch hold` can keep that default instead of a second input field. These are recommendations, not changes in this PR.

## Replace with brief text

Row 38 qualifies today because the trap skills call it. Yet the worker already has its two-word name from sign-on and the current work from its dispatch. The skill can form and set the visible title directly, with the same truncation and best-effort rule. That removes a presentation-only CLI subcommand and its config switch while preserving the user's outcome. This is the closest surviving addition to the removed `push` command's shape: a worker can do it from the brief without new daemon state. If #88 keeps the command for a stable cross-client title policy, the owner should accept that explicit tradeoff.

## Remove

Row 2 has no caller beyond docs/tests. The daemon and pick already observe due watches; `prs sync` adds another way to advance them. Row 22 deliberately leaves mail where no worker will read it, while the normal `send` safely wakes the finished chain. Row 39 has no caller even in the #88 skills: they use the plain `soak title` output. Remove only after any documented/manual usage is considered. No behavior is changed by this audit.

## Overlaps and behavior growth

- `attention ack/unack` is display-only state used by the pet and glass lobs. The pet **reads** `attention --json`; it does not acknowledge items itself. There is no duplicate pet ack command. `man tend --json` is the pet's old fallback and carries a larger payload. Both are still supported.
- `watch hold` and its optional `--for` protect a worker-owned PR branch; the daemon/pick enforce the hold. A repair's own `heldBy` wait is automatic when a live worker owns that branch. The manual hold is for work the daemon cannot infer, such as pushing to another PR. `watch release` clears explicit, cap, and cancelled-repair holds; it does not replace a repairer's report.
- `soak --wait` is the trap's foreground assignment/inbox waiter. `man wait` is the lobstah man's foreground fleet-attention waiter. They have different identities, gates, and outputs; they are not interchangeable. `man haul --park` is a Stop-hook mode, not a third foreground wait command.
- `daemon status`, `glass status`, and `doctor` overlap in reporting health. The two status verbs are narrow service checks; `doctor` diagnoses dependencies. `glass restart` and `daemon restart` likewise share a verb but operate on different service lifecycles.
- `send` now creates a follow-up when a chain is finished (#75), rather than only sending mail. That is substantial behavior growth behind old syntax. #70 also changed `cull` to automatic retention and `--apply` to no longer measure size; #73 adds release-on-merge worktree cleanup; #91 currently records push failure from `report failed`. These are not new command/option spellings, but deserve review when assessing growth.

## Skill and usage consistency

The trap skills on `main` tell a session to run `soak`, `soak --repo`, `soak --one`, `soak --wait --timeout`, `report` with its six verbs and pause flags, `inbox`, `stow`, and `stow --keep`. The #86 skill heads add `soak --link`; #88 adds `soak title`. All exist in their corresponding `usage.ts` registries and implementations. The lobstah man skills call `man helm`, `man relieve`, `glass --detach`, `dispatch --repo --brief --for`, `send`, `status`, `catch`, `cancel`, `man tend`, `man report`, `man wait --peek --session --timeout`, and document `watch hold/release` and `man haul --park`; those also exist and match the generated synopsis. Codex skill examples supply `--session` where needed. The hook manifests call bare `man brief`, `man haul`, `soak beat`, and `stow --quiet`, all implemented.

The registry drives flag validation and synopsis generation. A search of option reads in `main.ts` found no newly implemented flag absent from `usage.ts`, and no newly registered flag with no parser read. There are **scope** ambiguities: `soak --json` in #88 is registered for all `soak` forms but read only in `soak title`; `watch --reason` applies only to `hold`, `watch --apply` only to `backfill`, `watch --all` only to `release`, and `daemon --force` only to `restart`. The broad registry accepts some combinations whose flags have no effect. There are also synopsis/prose mismatches: `status` still prints `[<uuid>]`, `send` prints `<uuid>|wt:<trap>`, and `dispatch --for` prints `wt:<trap>` although each accepts a trap name; their prose documents names. The synopsis should catch up even if the behavior stays. No other implemented-versus-documented addition mismatch was found in the compared heads.

## Proposed removal order

1. Remove `send --harness`, `--model`, and `--for` after updating any tests and examples to use `dispatch --follow-up`. This breaks callers that set follow-up placement through `send`; repo search found only tests, but external scripts are unknown. Keep plain `send` and finished-chain wake behavior.
2. Remove `soak title --json`, then replace `soak title` with skill title instructions if the owner accepts the presentation boundary. This breaks the #88 trap skills and any title tooling that parses the JSON; update both skills first. It does not break daemon claims or dispatch titles, which are recorded separately.
3. Remove `prs sync` after confirming daemon/pick refresh is enabled for all supported installations. This breaks manual immediate refresh scripts; a person can use `watch check-pr` for a specific watch or wait for the next cycle. `prs` remains a read-only listing.

Next candidates are `send --no-wake`, `watch hold --reason`, and eventually both `watch backfill` forms after the one-time migration is complete. None is removed here.
