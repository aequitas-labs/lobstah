How it works

A daemon does the watching, with no model in the loop.

  1. You lob a brief. Each job gets its own git worktree.
  2. The daemon supervises. It tells a dead worker from a stuck one and recovers each.
  3. It wakes you only when needed. A catch, or a question.

The lobstah man

One Claude Code or Codex session takes the helm. You talk to it; it sends out the work and brings you the catch.

  • /lobstah:man
  • each question is a card on the glass
autonomous

The background router

No session open. Lob in a brief, or let your tracker do it. lobstah pings you when a worker needs you.

  • lobstah dispatch
  • pings through any command you choose

Both run on the same daemon. Start with the router and add a helm when you like.

Claude Code Codex

Bring your own harness

A trap can be a CLI session or a desktop app session, on Claude Code or Codex. Any session you already have open can opt in as a trap, and then the helm directs it.

Integrations

No webhooks, no tunnel. lobstah polls.

  • PRs Workers open pull requests on GitHub. lobstah watches checks, reviews and conflicts, and repairs what it can.
  • PR stacks One wake when a whole stack is ready, bottom first.
  • Issues Assign an issue on GitHub or Linear and it becomes a job. Status comes back as comments.
  • PR reviews PR links open where you review: GitHub, Graphite or Linear.
  • CI lobstah watch stands watch on a CI run, or anything with a command line.
  • Notifications One command of yours runs when a worker needs you: post to Slack, ntfy, anything.
  • OpenClaw Four tools and /lobstah for your fleet's agents.
